Ad tabs appeared during these follow-up interactions. One appeared before the other two embed destinations were opened, identifying Vidsrc.su as a popup source in this browser. Later tabs cannot all be assigned to one source because other ad-bearing pages were open. This was not a uBlock-on versus uBlock-off comparison and cannot establish which ads default uBlock lists already prevent.

The live page contains a separate optional inline loader that registers `window.addEventListener("load", ...)` and injects `rq.alchemmauls.com` plus an analytics script. The code explicitly ignores script-load failures. A third candidate targets that loader at registration using the ad-domain signature. It also skips the analytics script in the same loader. Playback and popup regression with this candidate active remain unverified.

## Proposed rules and validation

Three source-based rules are staged in [the candidate file](../candidates/streaming-players.txt). The existing five active filters and all three candidate rules pass the pinned upstream uBlock static filter parser. This verifies syntax, not successful injection, zero flicker, or playback regression on the live sites.

The candidate file is excluded from the main subscription. Promotion requires a full-uBlock test with logger evidence that the intended script was aborted, no new tab was created, and playback and normal controls still work. The active list is not being expanded on the strength of an unfiltered-browser audit alone.
